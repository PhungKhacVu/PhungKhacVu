## 2024-05-24 - Database I/O Optimization
**Learning:** Reading from the disk (e.g., `fs.readFile`) on every API request is a major performance bottleneck for this application. Using an in-memory variable to cache the data can improve read speeds significantly. However, since the route handlers mutate the data they get from the database file, just passing the array directly leads to "cache poisoning" where mutated data can bypass being correctly written to disk or be accidentally served to other users.
**Action:** Use a stringified JSON variable (`cachedPromptsString`) for the cache. By parsing this string (acting as a deep copy via `JSON.parse`) in a `try-catch` block on every read request, the cache avoids cache poisoning while safely invalidating on invalid JSON. Update the cache only after a successful disk write, and return an empty array on read errors without caching the error state.
